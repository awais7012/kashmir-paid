# Taste
- Prefers building backends with Node.js + Express (self-hosted code) over managed BaaS platforms like Supabase; explicitly wants to move off Supabase. Confidence: 0.7
- Prefers to be handed the exact commands to run himself rather than have the assistant execute them ("don't run, give me the command to run it"). Confidence: 0.6
- Non-technical, shorthand-typing user (frequent typos, e.g. "what is teh admin meial and passrd", "give amdin to cahe it login passrd"): asks basic operational questions and wants plain-language, copy-pasteable, step-by-step answers rather than internal implementation detail. Confidence: 0.7
- Wants an admin/CMS with full control over site content (copy, navigation, images, video, broadcast); objects when the panel can only edit a headline/summary. Confidence: 0.7
- Expects homepage content (e.g. the hero) to have its own explicit admin control, not to be an implicit side-effect of another field (like the hero image being derived from whichever story is marked "featured"). Confidence: 0.6
- Expects every button, link and section to actually work — no dead buttons, placeholder modals, or broken `#` anchor links left in the UI. Confidence: 0.65
- Wants editors to be able to upload their own images and video, not just pick from bundled assets. Confidence: 0.6
- Expects each major feature to have a dedicated, discoverable admin area with a real management flow (e.g. a broadcast screen with a go-live/end control and a plain-language status of what viewers currently see) rather than a lone buried checkbox under a general Settings page. Confidence: 0.55
- Wants account-level admin controls to be self-service in the studio (change the login password themselves from an Account screen) rather than a developer-managed credential. Confidence: 0.6
- Serves an Urdu-speaking audience and wants Urdu treated as a first-class content language: editors should be able to write and publish stories and category names in Urdu, and the public site should render that text properly right-to-left in an Urdu typeface, not English-only. Confidence: 0.6
- Scopes features to content, not chrome: was happy to have story text and category names in Urdu while leaving fixed interface labels (buttons, nav, footer, timestamps) in English. Confidence: 0.5
- Self-hosts on a single budget VPS rather than a PaaS/managed platform (buys a small Hostinger KVM box and runs the whole stack there), so deployment guidance should target one Linux server with nginx + PM2 + MySQL on a single domain. Confidence: 0.55
- Triages fixes into prioritized batches: after an audit he picks a subset to fix now and explicitly defers the rest ("Leave the rest ... for later"), favoring user-visible bugs (hero/featured logic, data-loss / unsaved-changes protection, media safety) and deploy-critical operational gaps (image optimization, DB/uploads backups, dependency audit) over code hygiene like tests, README updates, and secondary security hardening. Confidence: 0.55
- Reports problems by pasting raw terminal/server output (a failing API call, stack trace, HTTP status codes) with little or no accompanying instruction, expecting the assistant to diagnose the root cause and apply the fix rather than being told exactly what to do. Confidence: 0.5
